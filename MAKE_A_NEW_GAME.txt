HOW TO MAKE YOUR NEXT MATCH-UP GAME
===================================

After V6 is installed, this is the normal workflow.

YOU NEED ONLY:
  index.html
  game.json
  images/


EXAMPLE: CELL ORGANELLES
-------------------------
1. Create a new GitHub repository, for example:

   Matchup-Cells

2. Copy the V6 index.html into that repository.

3. Copy game_TEMPLATE.json into the repository and rename it:

   game.json

4. Upload your card images into:

   images/


EDIT ONLY game.json
--------------------
Example:

{
  "id": "cell-organelles-01",
  "title": "CELL ORGANELLES MATCH-UP",
  "instructions": "Choose a definition, then choose the matching organelle.",
  "workerUrl": "https://matchup-leaderboard.sliggett.workers.dev",
  "columns": 5,
  "definitionExtension": ".png",
  "imageExtension": ".png",
  "pairs": {
    "A": "06",
    "B": "02",
    "C": "09",
    "D": "01",
    "E": "04",
    "F": "10",
    "G": "03",
    "H": "08",
    "I": "05",
    "J": "07"
  }
}


THE IMPORTANT PART
------------------
Every game needs a UNIQUE id.

Good:
  cell-organelles-01
  body-systems-02
  ecology-food-webs-01

Bad:
  My Game!
  Cells 1

Use:
  lowercase letters
  numbers
  hyphens


THE ANSWER KEY
--------------
The pairs object IS the answer key.

For example:

  "A": "06"

means:
  definition card A.png
matches
  picture card 06.png


FILENAMES
---------
If game.json contains:

  "A": "06"

then these files must exist:

  images/A.png
  images/06.png


TURN ON GITHUB PAGES
--------------------
Repository:
Settings
→ Pages
→ Deploy from a branch
→ main
→ /(root)

Your game will then have an address such as:

https://sliggett-hash.github.io/Matchup-Cells/


SCHOOLOGY
---------
Add a Link and use the GitHub Pages URL.

Keep:
  Display in Schoology

If Schoology's frame is too small, students can open it in a new tab.


LEADERBOARDS
------------
Nothing else is required.

The Worker reads the game's unique ID and automatically keeps that
game's leaderboard separate.

Each game gets its own:
  All-Time Record
  Today's Champion
  Live Top 10

The expiration rules remain:
  #1 today → until midnight America/Detroit time
  #2–#10 → 30 minutes
  all-time record → permanent

**** MORE OR LESS CARDS ****
The template currently supports 2–20 matching pairs, and the number of matches automatically comes from game.json.
For example, if you only had 6 pairs, your game.json could simply contain:
"columns": 3,

"pairs": {
  "A": "01",
  "B": "02",
  "C": "03",
  "D": "04",
  "E": "05",
  "F": "06"
}
You would upload:
A.png – F.png
01.png – 06.png
The game would automatically say:
Matches: 0/6
and finish after six correct matches.
For 15 pairs, you could do:
"columns": 5,

"pairs": {
  "A": "01",
  "B": "02",
  "C": "03",
  "D": "04",
  "E": "05",
  "F": "06",
  "G": "07",
  "H": "08",
  "I": "09",
  "J": "10",
  "K": "11",
  "L": "12",
  "M": "13",
  "N": "14",
  "O": "15"
}
And upload:
A.png – O.png
01.png – 15.png
Everything else adjusts automatically: number of cards, match counter, game completion, server verification, leaderboard, scoring, and answer key.
The columns setting just controls how many cards appear across the screen. I’d generally use:
4–6 pairs → columns: 3
7–12 pairs → columns: 4 or 5
13–20 pairs → columns: 5
One important advantage of the V6 system is that each game has its own leaderboard, so a 20-pair game's much larger possible score doesn't compete against a 6-pair game's scores.
So next time, you can give me 7 pairs, 12 pairs, 18 pairs, etc., and we just put exactly those pairs in game.json. No rebuilding the game engine.
